## 一、文档概述

### 1.1 设计目标

本文档定义 Clicker Quest 游戏的经济曲线系统，确保：
- **稳定的数值增长**：避免通货膨胀和数值溢出
- **合理的游戏节奏**：前中后期体验流畅
- **长期可玩性**：支持长期运营和内容扩展
- **数值可调整性**：便于后期优化和平衡

### 1.2 核心原则

1. **产出略大于消耗**：保持玩家成长感，避免卡顿
2. **边际递减效应**：后期增长放缓，延长游戏寿命
3. **多维度成长**：点击、自动、成就、道具多线并行
4. **数值上限控制**：防止溢出，确保系统稳定

## 二、金币产出公式

### 2.1 点击产出公式

#### 基础公式
```
点击产出 = 基础点击值 × (1 + 点击加成) × 暴击倍数
```

#### 参数定义
- **基础点击值**: 初始为 1 金币/次
- **点击加成**: 通过升级和道具获得，最高 +500%
- **暴击倍数**: 基础 1.0，暴击时 2.0-10.0

#### 详细公式
```
点击产出(t) = Base_Click × (1 + Click_Bonus(t)) × Crit_Multiplier

其中:
- Base_Click = 1 (初始值)
- Click_Bonus(t) = 0.1 × Click_Level(t) + Σ(道具加成)
- Crit_Multiplier = 1.0 (普通) 或 random(2.0, 10.0) (暴击)
```

#### 升级成本公式
```
点击升级成本(n) = 15 × 1.07^n

其中:
- n = 当前点击等级
- 每次升级提升 10% 点击产出
```

### 2.2 自动产出公式 (DPS)

#### 基础公式
```
DPS = Σ(每个自动点击器的产出)
```

#### 单个自动点击器产出
```
自动产出(i) = Base_DPS(i) × (1 + DPS_Bonus)

其中:
- Base_DPS(i) = 第 i 个自动点击器的基础产出
- DPS_Bonus = 通过道具和升级获得的加成
```

#### 自动点击器价格公式
```
价格(n) = Base_Price × Price_Multiplier^n

其中:
- Base_Price = 基础价格(不同类型不同)
- Price_Multiplier = 价格倍率(1.07-1.15)
- n = 已购买数量
```

#### 自动点击器参数表

| 类型 | 名称 | 基础产出(金币/秒) | 基础价格 | 价格倍率 | 解锁条件 |
|------|------|------------------|---------|---------|---------|
| 1 | 实习生 | 0.1 | 15 | 1.07 | 初始 |
| 2 | 员工 | 1 | 100 | 1.08 | 100金币 |
| 3 | 主管 | 5 | 500 | 1.09 | 1000金币 |
| 4 | 经理 | 20 | 2000 | 1.10 | 5000金币 |
| 5 | 总监 | 100 | 10000 | 1.11 | 25000金币 |
| 6 | VP | 500 | 50000 | 1.12 | 100000金币 |
| 7 | CEO | 2000 | 200000 | 1.13 | 500000金币 |
| 8 | 董事会 | 10000 | 1000000 | 1.14 | 2000000金币 |
| 9 | 集团 | 50000 | 5000000 | 1.15 | 10000000金币 |
| 10 | 帝国 | 250000 | 25000000 | 1.15 | 50000000金币 |

### 2.3 总产出公式

#### 综合产出公式
```
总产出(t) = 点击产出(t) + DPS(t) + 成就奖励(t) + 离线收益(t)

其中:
- 点击产出(t) = 玩家主动点击获得的金币
- DPS(t) = 自动产出(每秒)
- 成就奖励(t) = 完成成就获得的一次性奖励
- 离线收益(t) = 离线期间的累积收益
```

#### 时间维度产出公式
```
累积金币(T) = ∫[0,T] DPS(t) dt + Σ(点击产出) + Σ(成就奖励)

简化计算:
累积金币(T) ≈ DPS_avg × T + Click_Total + Achievement_Total
```

## 三、通胀控制方案

### 3.1 通胀控制原理

#### 核心机制
1. **价格指数增长**：道具价格按指数增长，控制购买速度
2. **产出边际递减**：后期产出增长放缓，延长游戏寿命
3. **软上限机制**：达到一定数值后，产出效率降低
4. **硬上限设置**：设置绝对数值上限，防止溢出

### 3.2 价格曲线设计

#### 价格增长公式
```
价格(n) = Base × Multiplier^n

设计原则:
- 前期(1-10个): 倍率 1.07，快速购买
- 中期(11-50个): 倍率 1.10，稳定成长
- 后期(51-100个): 倍率 1.15，缓慢成长
- 极限(100+个): 倍率 1.20，追求极限
```

#### 价格增长曲线表

| 购买数量 | 倍率 | 价格增长倍数 | 累计投入 |
|---------|------|-------------|---------|
| 1-10 | 1.07 | 1.0-1.97x | 15-206 |
| 11-25 | 1.08 | 2.0-6.85x | 206-2580 |
| 26-50 | 1.10 | 6.9-98.1x | 2580-49700 |
| 51-100 | 1.12 | 98.5-28900x | 49700-1.45e+7 |
| 101-200 | 1.15 | 28950-8.36e+8x | 1.45e+7-4.18e+11 |

### 3.3 产出控制机制

#### 软上限公式
```
实际产出 = 基础产出 × 软上限系数

软上限系数 = 1 / (1 + (当前DPS / 软上限阈值)^0.5)

其中:
- 软上限阈值 = 1e+12 (可根据游戏阶段调整)
```

#### 软上限效果表

| 当前DPS | 软上限系数 | 实际产出效率 |
|---------|-----------|-------------|
| 1e+6 | 1.000 | 100% |
| 1e+9 | 0.999 | 99.9% |
| 1e+12 | 0.707 | 70.7% |
| 1e+15 | 0.500 | 50.0% |
| 1e+18 | 0.316 | 31.6% |

### 3.4 硬上限设置

#### 数值上限表

| 数值类型 | 上限值 | 原因 |
|---------|-------|------|
| 金币数量 | 1.79e+308 | JavaScript Number.MAX_VALUE |
| DPS | 1e+15 | 显示和计算安全范围 |
| 点击加成 | +500% | 避免过度膨胀 |
| 道具数量 | 1000/类型 | 防止内存溢出 |
| 升级等级 | 1000 | 合理的成长上限 |

### 3.5 通胀监控指标

#### 监控公式
```
通胀率 = (当前平均DPS / 初始平均DPS) / (当前游戏时长 / 初始游戏时长)

健康范围: 通胀率 < 10
警告范围: 10 ≤ 通胀率 < 50
危险范围: 通胀率 ≥ 50
```

#### 调整策略
- **健康状态**：保持当前设计
- **警告状态**：提高价格倍率，降低产出加成
- **危险状态**：引入新的消耗机制，调整核心公式

### 4.3 节奏曲线公式

#### 综合节奏公式
```
累计金币(T) = f(T)

其中:
- T ∈ [0, 5分钟]: f(T) = 15 × T^2 (指数增长)
- T ∈ [5分钟, 2小时]: f(T) = 5000 × T + 500 (线性增长)
- T ∈ [2小时, +∞]: f(T) = 1e+9 × log(T/2) + 1e+9 (对数增长)
```

#### 节奏验证指标
```
成长速度 = d(累计金币) / dT

健康范围:
- 新手期: 成长速度 > 100/分钟
- 成长期: 成长速度 > 1000/分钟
- 稳定期: 成长速度 > 10000/分钟
- 长期: 成长速度 > 100000/分钟
```

| 24小时 | 1e+15 | 6e+14 | 1.67 | 正常 |

**设计说明**：
- 产出/消耗比保持在 1.6-1.7 之间
- 确保玩家有足够的金币进行升级和购买
- 避免金币过多导致通货膨胀

ROI周期 = 价格 / (DPS × 60)

## 六、数值验证方案

### 6.1 模拟测试方案

#### 测试场景设计

| 测试场景 | 测试时长 | 测试目标 | 验证指标 |
|---------|---------|---------|---------|
| 新手体验 | 5分钟 | 验证新手引导节奏 | 累计金币 > 500 |
| 快速成长 | 30分钟 | 验证成长速度 | 累计金币 > 500000 |
| 稳定成长 | 2小时 | 验证中期平衡 | 累计金币 > 1e+9 |
| 长期运营 | 24小时 | 验证长期稳定性 | 累计金币 > 1e+15 |
| 极限测试 | 100小时 | 验证数值上限 | 无溢出错误 |

#### 测试数据收集

**必须收集的数据**：
1. 每分钟的累计金币
2. 每分钟的DPS
3. 每次购买后的金币余额
4. 每次升级后的产出变化
5. 暴击触发次数和效果
6. 离线收益计算结果

### 6.2 数值调整原则

#### 调整原则

1. **小幅调整原则**
   - 每次调整幅度不超过 20%
   - 避免大幅调整影响玩家体验
   - 调整后必须重新测试验证

2. **数据驱动原则**
   - 基于实际数据调整
   - 避免主观臆断
   - 收集玩家反馈作为参考

3. **平衡性原则**
   - 保持产出/消耗比在 1.5-2.0 之间
   - 确保所有道具有购买价值
   - 避免某个道具过于强势

4. **可逆性原则**
   - 所有调整必须有回滚方案
   - 保留调整前的数值参数
   - 记录调整原因和效果

#### 调整流程

```
数据收集 → 问题分析 → 方案设计 → 测试验证 → 上线实施 → 效果监控
    ↑                                                        ↓
    ←←←←←←←←←←←←←←←← 问题反馈 ←←←←←←←←←←←←←←←←←←←←←←←←←←←←←
```

### 6.3 应急调整预案

#### 预案1: 数值膨胀过快

**触发条件**：
- 产出/消耗比 > 2.5
- 玩家平均金币余额 > 预期的 150%
- 玩家反馈"金币太多没处花"

**调整方案**：
1. 提高道具价格倍率 (1.07 → 1.10)
2. 降低产出加成效果 (-20%)
3. 引入新的消耗机制 (金币抽奖、金币商店)
4. 增加高级道具的购买成本

#### 预案2: 数值增长过慢

**触发条件**：
- 产出/消耗比 < 1.2
- 玩家平均金币余额 < 预期的 50%
- 玩家反馈"金币不够用"

**调整方案**：
1. 降低道具价格倍率 (1.10 → 1.07)
2. 提高产出加成效果 (+20%)
3. 增加成就奖励金额
4. 增加限时道具的获取频率

#### 预案3: 道具性价比失衡

**触发条件**：
- 某个道具购买率 > 80%
- 某个道具购买率 < 5%
- 玩家反馈"某个道具太强/太弱"

**调整方案**：
1. 调整强势道具的价格或效果 (-15%)
2. 调整弱势道具的价格或效果 (+15%)
3. 重新计算投资回报周期
4. 更新道具性价比表

## 七、文档总结

### 7.1 核心设计要点

1. **金币产出公式**：
   - 点击产出 = 基础值 × (1 + 加成) × 暴击倍数
   - DPS = Σ(自动点击器产出)
   - 总产出 = 点击 + DPS + 成就 + 离线

2. **通胀控制方案**：
   - 价格指数增长 (倍率 1.07-1.15)
   - 产出边际递减 (软上限机制)
   - 硬上限设置 (金币 1.79e+308, DPS 1e+15)

3. **节奏设计**：
   - 新手期 (0-5分钟): 指数增长
   - 成长期 (5分钟-2小时): 线性增长
   - 长期 (2小时+): 对数增长

4. **数值参数**：
   - 产出/消耗比: 1.6-1.7
   - 投资回报周期: 1.5-2.5分钟
   - 道具性价比: S-D 五级评级

### 7.2 关键成功指标

| 指标 | 目标值 | 验证方法 |
|------|-------|---------|

| 长期留存率 | > 20% | 24小时内达到 1e+15 金币 |
| 数值稳定性 | 100% | 无溢出错误、无负数异常 |
| 平衡性 | 产出/消耗比 1.5-2.0 | 数据监控和玩家反馈 |
