## 一、系统概述

### 1.1 系统定位

商店系统是Clicker Quest游戏中玩家消耗金币、获取道具的主要途径。作为连接金币系统和道具系统的核心枢纽，商店系统直接影响游戏的经济循环、玩家成长节奏和长期留存。

### 1.2 设计目标

**核心目标**:
- 提供清晰易用的商店界面，降低玩家学习成本
- 建立合理的购买规则，引导玩家合理消费
- 创造有吸引力的道具展示，激发购买欲望
- 维护游戏经济平衡，避免通货膨胀

**用户体验目标**:
- 3秒内找到想要的道具
- 2步内完成购买操作
- 1秒内获得购买反馈
- 0误操作导致损失

### 1.3 系统关联

```
金币系统(SD-1) → 商店系统(SD-2) → 道具系统(SD-3)
      ↓                ↓                ↓
   金币消耗         道具购买          道具发放
      ↓                ↓                ↓
  数值策划(BD-2)   UI策划(UID-2)    道具策划(SD-3)
```

## 三、购买流程设计

### 3.1 购买前置条件

#### 3.1.1 金币数量检查

**检查逻辑**:
```
IF 玩家当前金币 >= 道具价格 THEN
    允许购买
ELSE
    显示金币不足提示
END IF
```

**检查时机**:
- 进入商店时: 更新所有道具的可购买状态
- 金币变化时: 实时更新道具状态
- 点击购买按钮时: 再次确认金币数量

#### 3.1.2 购买次数限制检查

**限制类型**:
| 限制类型 | 说明 | 示例 |
|---------|------|------|
| 单次购买 | 只能购买1次 | 新手礼包 |
| 限次购买 | 每日/每周限制次数 | 每日限购3次 |
| 无限购买 | 无购买次数限制 | 普通道具 |

**检查逻辑**:
```
IF 道具购买类型 == "单次购买" THEN
    IF 已购买次数 >= 1 THEN
        显示"已售罄"
        禁止购买
    END IF
ELSE IF 道具购买类型 == "限次购买" THEN
    IF 今日已购买次数 >= 每日上限 THEN
        显示"今日已售罄"
        禁止购买
    END IF
ELSE
    允许购买
END IF
```

#### 3.1.3 道具解锁条件检查

**解锁条件类型**:
| 条件类型 | 说明 | 示例 |
|---------|------|------|
| 等级限制 | 达到指定等级解锁 | 10级解锁 |
| 前置道具 | 购买前置道具后解锁 | 购买初级自动点击器后解锁中级 |
| 成就解锁 | 完成指定成就解锁 | 完成"初次点击"成就 |
| 时间解锁 | 达到指定时间解锁 | 游戏时间达到1小时 |

**检查逻辑**:
```
IF 道具有解锁条件 THEN
    IF 玩家满足解锁条件 THEN
        显示道具，允许购买
    ELSE
        显示锁定状态，显示解锁条件
        禁止购买
    END IF
ELSE
    显示道具，允许购买
END IF
```

### 3.2 购买流程

#### 3.2.1 标准购买流程

```
开始
  ↓
玩家点击购买按钮
  ↓
检查金币数量 → 不足 → 显示金币不足提示 → 结束
  ↓ 足够
检查购买次数限制 → 达到上限 → 显示购买限制提示 → 结束
  ↓ 未达上限
检查解锁条件 → 未解锁 → 显示解锁条件提示 → 结束
  ↓ 已解锁
显示确认购买弹窗(可选)
  ↓
玩家确认购买
  ↓
扣除金币
  ↓
发放道具
  ↓
更新购买记录
  ↓
显示购买成功反馈
  ↓
结束
```

#### 3.2.2 快速购买流程(小额道具)

**适用条件**:
- 道具价格 < 当前金币的10%
- 道具非限时道具
- 道具购买次数无限制

**流程简化**:
```
点击购买按钮 → 扣除金币 → 发放道具 → 显示成功反馈
```

**优势**:
- 减少操作步骤
- 提升购买体验
- 降低决策成本

#### 3.2.3 确认购买弹窗设计

**弹窗内容**:
```
┌─────────────────────┐
│     确认购买         │
├─────────────────────┤
│  [图标] 道具名称     │
│         效果描述     │
│                     │
│  价格: 1000金币     │
│  当前金币: 5000金币  │
│  购买后剩余: 4000金币 │
│                     │
│  [取消]    [确认]   │
└─────────────────────┘
```

**交互行为**:
- 点击"取消": 关闭弹窗，不执行购买
- 点击"确认": 执行购买流程
- 点击弹窗外部: 关闭弹窗

### 3.3 异常处理

#### 3.3.1 金币不足处理

**处理流程**:
```
检测到金币不足
  ↓
显示金币不足弹窗
  ↓
玩家选择操作
  ├─ 点击"取消" → 关闭弹窗
  └─ 点击"去获取" → 显示获取金币途径
```

**获取金币途径提示**:
```
┌─────────────────────┐
│    获取金币途径      │
├─────────────────────┤
│  1. 继续点击获取金币  │
│  2. 观看广告获取金币  │
│  3. 完成成就获取金币  │
│                     │
│       [确定]        │
└─────────────────────┘
```

#### 3.3.2 购买次数已达上限处理

**处理流程**:
```
检测到购买次数已达上限
  ↓
更新道具状态为"已售罄"
  ↓
显示购买限制提示弹窗
  ↓
玩家点击"确定" → 关闭弹窗
```

**提示内容**:
- 单次购买: "该道具已购买，无法再次购买"
- 每日限购: "今日购买次数已达上限，请明天再来"
- 每周限购: "本周购买次数已达上限，请下周再来"

#### 3.3.3 网络异常处理

**处理流程**:
```
检测到网络异常
  ↓
显示网络异常提示
  ↓
保存购买请求到本地队列
  ↓
网络恢复后自动重试
  ↓
重试成功 → 显示购买成功
重试失败 → 显示购买失败，退还金币
```

**网络异常提示**:
```
┌─────────────────────┐
│     网络异常         │
│                     │
│  网络连接失败，请检查 │
│  网络设置后重试      │
│                     │
│  [取消]    [重试]   │
└─────────────────────┘
```

#### 3.3.4 数据保存失败处理

**处理流程**:
```
检测到数据保存失败
  ↓
显示保存失败提示
  ↓
本地缓存购买记录
  ↓
定时重试保存
  ↓
保存成功 → 清除本地缓存
保存失败 → 继续重试(最多3次)
```

**保存失败提示**:
```
┌─────────────────────┐
│     保存失败         │
│                     │
│  数据保存失败，正在  │
│  重试保存...        │
│                     │
│       [确定]        │
└─────────────────────┘
```

- 格式: 效果类型+数值+时间(如有)

### 4.3 排序规则

#### 4.3.1 默认排序

**排序优先级**:
1. 推荐道具(置顶)
2. 按价格升序
3. 按道具ID升序

**推荐道具标识**:
- 新手推荐: 新手礼包、初级自动点击器

#### 4.3.2 价格排序

**升序排序**:
- 从低到高排列
- 适合新手玩家快速购买

**降序排序**:
- 从高到低排列
- 适合高端玩家查看高级道具

#### 4.3.3 推荐排序

**推荐算法**:
```
推荐分数 = 购买次数 x 0.4 + 性价比 x 0.3 + 新手友好度 x 0.3
```

**排序规则**:
- 按推荐分数降序排列
- 每日更新推荐列表

#### 4.3.4 购买次数排序

**排序规则**:
- 按全服购买次数降序排列
- 显示"热门"标识
- 实时更新

#### 4.3.5 自定义排序

**排序选项**:
| 排序方式 | 说明 |
|---------|------|

## 六、购买限制规则设计

### 6.1 购买次数限制

#### 6.1.1 单次购买道具

**定义**: 只能购买1次，购买后无法再次购买

**适用道具**:
- 新手礼包
- 首充礼包
- 特殊成就奖励道具

**展示方式**:
- 未购买: 正常显示
- 已购买: 显示"已购买"，购买按钮禁用

**数据存储**:
```
购买记录 = {
    道具ID: item_special_newbie_pack,
    购买时间: 2026-02-20 10:30:00,
    购买次数: 1
}
```

#### 6.1.2 限次购买道具

**定义**: 在指定时间范围内限制购买次数

**限制类型**:
| 限制类型 | 时间范围 | 重置时间 | 示例 |
|---------|---------|---------|------|
| 每日限购 | 当天0:00-23:59 | 次日0:00 | 每日礼包(限购1次) |
| 每周限购 | 周一0:00-周日23:59 | 下周一0:00 | 每周礼包(限购3次) |

- 显示"今日剩余: 2/3"

**数据存储**:
```
购买记录 = {
    道具ID: item_special_daily_pack,
    购买时间: 2026-02-20 10:30:00,
    今日购买次数: 1,
    上次重置时间: 2026-02-20 00:00:00
}
```

#### 6.1.3 无限购买道具

**定义**: 无购买次数限制，只要有足够金币即可购买

**适用道具**:
- 普通道具类道具
- 升级类道具
- 基础自动点击器

**展示方式**:
- 正常显示
- 无购买次数提示

### 6.2 购买条件限制

#### 6.2.1 等级限制

**限制规则**:
| 道具类型 | 等级要求 | 说明 |
|---------|---------|------|
| 初级道具 | 1级 | 无限制 |
| 中级道具 | 5级 | 需达到5级 |
| 高级道具 | 10级 | 需达到10级 |
| 顶级道具 | 20级 | 需达到20级 |

**展示方式**:
- 未达到等级: 显示锁定图标，显示"需要X级解锁"
- 已达到等级: 正常显示

**检查逻辑**:
```
IF 玩家等级 >= 道具解锁等级 THEN
    显示道具，允许购买
ELSE
    显示锁定状态
    显示"需要X级解锁，当前等级: Y级"
END IF
```

#### 6.2.2 前置道具限制

**限制规则**:
| 道具ID | 前置道具 | 说明 |
|--------|---------|------|
| item_auto_002 | item_auto_001 | 需先购买初级自动点击器 |
| item_auto_003 | item_auto_002 | 需先购买中级自动点击器 |
| item_upgrade_click_002 | item_upgrade_click_001 | 需先购买点击金币升级I |

- 未购买前置道具: 显示锁定图标，显示"需要先购买XXX"
- 已购买前置道具: 正常显示

**检查逻辑**:
```
IF 前置道具已购买 THEN
    显示道具，允许购买
ELSE
    显示锁定状态
    显示"需要先购买[前置道具名称]"
END IF
```

#### 6.2.3 成就解锁限制

**限制规则**:
| 道具ID | 成就要求 | 说明 |
|--------|---------|------|

**展示方式**:
- 未完成成就: 显示锁定图标，显示"需要完成成就: XXX"
- 已完成成就: 正常显示

**检查逻辑**:
```
IF 成就已完成 THEN
    显示道具，允许购买
ELSE
    显示锁定状态
    显示"需要完成成就: [成就名称]"
END IF
```

### 6.3 购买冷却限制

#### 6.3.1 购买冷却时间

**限制规则**:
| 道具类型 | 冷却时间 | 说明 |
|---------|---------|------|
| 普通道具 | 无冷却 | 可连续购买 |
| 增益道具 | 30秒 | 购买后30秒内不可再次购买 |
| 特殊道具 | 60秒 | 购买后60秒内不可再次购买 |

**展示方式**:
- 冷却中: 显示"冷却中: 29秒"，购买按钮禁用
- 冷却结束: 正常显示

**检查逻辑**:
```
IF 当前时间 - 上次购买时间 >= 冷却时间 THEN
    允许购买
ELSE
    显示冷却中
    显示剩余冷却时间
END IF
```

#### 6.3.2 冷却时间显示

**显示位置**: 购买按钮上

**显示格式**:
- 大于1分钟: "冷却: 1:30"
- 小于1分钟: "冷却: 30秒"

**重置条件**:
- 冷却时间自然结束
- 使用钻石立即重置(可选功能)
- 每日0:00重置所有冷却(可选)

**重置逻辑**:
```
IF 冷却时间结束 OR 使用钻石重置 THEN
    清除冷却状态
    允许购买
END IF
```

## 十、风险提示

### 10.1 用户体验风险

**风险描述**: 商店界面复杂，玩家难以找到想要的道具

**应对措施**:
- 优化分类和搜索功能
- 提供推荐排序
- 添加道具搜索功能
- 提供道具筛选功能

### 10.2 经济平衡风险

**风险描述**: 道具价格不合理，影响游戏经济

**应对措施**:
- 与数值策划紧密协作
- 多轮测试调整
- 收集玩家反馈
- 建立数据监控机制

### 10.3 性能风险

**风险描述**: 道具过多导致加载缓慢

**应对措施**:
- 分页加载
- 优化资源管理
- 使用对象池技术
- 建立性能监控机制

### 10.4 安全风险

**风险描述**: 购买逻辑存在漏洞，可能被利用

**应对措施**:
- 服务端验证所有购买请求
- 记录所有购买日志
- 建立异常检测机制
- 定期安全审计
