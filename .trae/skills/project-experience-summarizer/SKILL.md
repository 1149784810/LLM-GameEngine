# 项目开发经验总结

## 触发时机

**CRITICAL**: 此技能有三个触发时机：

### 时机1：项目开发完成后（主要）
在全栈游戏开发引擎(fullstack-game-engine)执行完毕后立即调用，进行Bug收集和经验总结。

### 时机2：新项目需求分析阶段（查询模式）
在主策划完成需求拆分后，**主策划通过项目负责人**调用此技能查询经验库，获取历史经验指导当前项目。

**查询模式流程**：
```
主策划完成需求拆分
    ↓
项目负责人调用 project-experience-summarizer（查询模式）
    ↓
读取 experience-db.md 经验库
    ↓
根据项目类型筛选相关经验
    ↓
根据需求关键词匹配历史问题
    ↓
生成《经验借鉴报告》
    ↓
将报告附加到需求文档中
    ↓
主策划根据经验调整设计，规避已知问题
```

### 时机3：测试阶段（测试模式）⭐新增
在Phase 3第3位测试阶段，**主测试(LT)和子QA**需要频繁读写经验库。

**测试模式流程**：
```
Phase 3 第3位-1：主测试(LT)阻塞任务
    ↓
主测试读取 experience-db.md 经验库
    ↓
识别历史风险点，制定测试重点
    ↓
分配测试任务给子QA，告知历史风险
    ↓
Phase 3 第3位-2：子QA并行测试
    ↓
每个子QA测试前读取经验库
    ↓
测试时对比历史问题，避免重复犯错
    ↓
发现新问题 → 记录Bug → 修复 → 验证
    ↓
【强制】记录经验到经验库
    ↓
【强制】更新缓存计数
    ↓
Phase 3 第3位-3：主测试(LT)汇总
    ↓
汇总所有新问题，更新经验库
    ↓
形成测试→发现→修复→记录→更新的完整闭环
```

### 时机4：Bug修复后（记录模式）⭐新增
**每次修复Bug后必须立即记录经验**，这是强制要求。

**记录模式流程**：
```
Bug修复完成并验证通过
    ↓
【强制】调用经验记录流程
    ↓
1. 分析Bug根本原因
2. 提取关键词
3. 生成经验记录
4. 匹配缓存条目
    ↓
执行记录命令:
node bug-experience-recorder.js record --bug-id=<BugID>
    ↓
自动完成:
- 追加到 experience-db.md
- 更新缓存计数
- 生成经验文档
    ↓
经验记录完成
```

**强制检查点**：
- [ ] Bug已修复并验证通过
- [ ] 已分析根本原因
- [ ] 已记录经验到 experience-db.md
- [ ] 已更新缓存计数（如匹配）
- [ ] 已生成经验记录文档

## 核心职责

1. **主动询问Bug**: 在全栈开发完成后，主动询问用户"项目已完成，请问是否还有其他bug或问题需要修复？"
2. **Bug解决循环**: 
   - 接收用户反馈的bug
   - 分析问题原因
   - 提供解决方案
   - 实施修复
   - 再次询问是否还有其他问题
3. **经验总结**: 每次解决bug后，立即总结经验并记录
4. **循环直至满意**: 持续询问-解决-总结，直到用户回复"满意"或"没有问题"


## 经验库管理

### 文件结构

经验库由以下文件组成：

| 文件 | 路径 | 用途 |
|------|------|------|
| **经验库主文档** | `experience-db.md` | 存储完整的经验记录 |
| **缓存索引表** | `experience-cache-index.md` | 多级缓存索引，支持快速查询 |
| **缓存管理器** | `experience-cache-manager.js` | 缓存管理工具 |

### 缓存索引系统 ⭐新增

为了提高经验库的使用效率，引入了**多级缓存索引系统**：

#### 缓存级别

| 级别 | 名称 | 阈值 | 检查优先级 | 说明 |
|------|------|------|-----------|------|
| **L0** | Critical | 计数 >= 10 | 最高 | QA测试时必须逐项检查 |
| **L1** | High | 计数 >= 5 | 高 | 建议逐项检查 |
| **L2** | Medium | 计数 >= 2 | 中 | 按需检查 |
| **L3** | Low | 计数 >= 1 | 低 | 参考检查 |

#### 升级/降级规则

```
匹配计数增加
    ↓
达到升级阈值
    ↓
自动升级到更高级别
    ↓
长期未匹配
    ↓
自动降级/归档
```

**升级阈值**：
- L3 → L2: 计数达到 2
- L2 → L1: 计数达到 5
- L1 → L0: 计数达到 10

**降级策略**：
- L0: 30天无匹配 → 降级到 L1
- L1: 20天无匹配 → 降级到 L2
- L2: 15天无匹配 → 降级到 L3
- L3: 30天无匹配 → 归档到历史库

#### 关键词匹配

缓存索引支持四种匹配方式：

| 匹配类型 | 权重 | 说明 |
|---------|------|------|
| 精确匹配 | 1.0 | 关键词完全匹配 |
| 模糊匹配 | 0.8 | 关键词包含关系 |
| 语义匹配 | 0.6 | 同义词匹配 |
| 上下文匹配 | 0.4 | 相同上下文匹配 |

#### 使用流程

**QA测试阶段**：
```
主测试(LT)准备测试计划
    ↓
查询缓存索引表（按项目类型和关键词）
    ↓
从L0开始逐项检查
    ↓
L0: 必须检查
L1: 建议检查
L2/L3: 按需检查
    ↓
发现问题 → 匹配缓存条目 → 计数+1
    ↓
更新缓存索引表
```

**工具使用**：
```bash
# 查询缓存
node experience-cache-manager.js query --type=Web游戏 --keywords=ES Module,DOM事件

# 匹配缓存（计数+1）
node experience-cache-manager.js match --id=L0-001 --project=新项目A

# 生成检查清单
node experience-cache-manager.js checklist --type=Web游戏

# 执行降级检查
node experience-cache-manager.js downgrade

# 查看统计
node experience-cache-manager.js stats
```

## 经验应用

### 查询模式：新项目需求分析阶段

在主策划完成需求拆分后，**必须**执行以下步骤：

1. **读取经验库**: 
   - 读取 `experience-db.md` 文件
   - 检查是否有相关项目类型的经验

2. **识别相关经验**: 
   - 根据当前**项目类型**（RPG/SLG/休闲/动作等）筛选经验
   - 根据**需求关键词**（如"技能系统"、"UI布局"、"网络同步"等）匹配历史问题
   - 根据**技术栈**（Unity/Web/Node.js等）筛选技术相关问题

3. **生成《经验借鉴报告》**: 
   ```markdown
   # 经验借鉴报告
   
   ## 项目信息
   - 项目名称：[当前项目名称]
   - 项目类型：[RPG/SLG/休闲等]
   - 查询时间：[YYYY-MM-DD HH:MM]
   
   ## 相关历史经验
   
   ### 经验1：[问题类型] - [简要描述]
   - **来源项目**：[历史项目名称]
   - **问题描述**：[具体问题]
   - **根本原因**：[原因分析]
   - **对本项目的启示**：[如何避免]
   - **建议措施**：[具体行动]
   
   ### 经验2：...
   
   ## 风险预警
   
   | 风险点 | 历史发生次数 | 严重程度 | 预防措施 |
   |--------|-------------|---------|---------|
   | [风险1] | X次 | 高/中/低 | [措施] |
   | [风险2] | X次 | 高/中/低 | [措施] |
   
   ## 设计建议
   
   基于历史经验，建议在本项目中：
   1. [建议1]
   2. [建议2]
   3. [建议3]
   
   ## 需要特别注意的功能点
   
   - [功能点1]：历史上曾出现[X]次问题，建议...
   - [功能点2]：历史上曾出现[X]次问题，建议...
   ```

4. **前置规避**: 
   - 将《经验借鉴报告》附加到需求文档中
   - 在需求评审会议上重点讨论历史风险点
   - 在验收标准中增加针对历史问题的检查项

5. **预防性措施**: 
   - 主策划根据经验调整设计方案
   - 在任务分派时，特别提醒子策划注意已知风险
   - 在开发规范中明确规避措施

### 总结模式：项目开发完成后

在全栈开发完成后，按照以下流程执行：

1. **主动询问Bug**: 询问用户是否还有其他问题
2. **Bug解决循环**: 分析问题、提供方案、实施修复
3. **经验总结**: 记录问题原因、解决方案、预防措施
4. **更新经验库**: 将新经验添加到 `experience-db.md`

### 测试模式：测试阶段使用 ⭐新增

在Phase 3第3位测试阶段，主测试(LT)和子QA需要频繁读写经验库。

#### 主测试(LT)经验库使用流程

```

    ↓

    ↓

    ↓

    ↓

    ↓

    ↓
```

**主测试经验库操作**：

- **分析**: 分析历史问题分布和趋势
- **应用**: 将历史经验应用到测试计划中
- **更新**: 测试结束后汇总新问题并更新经验库

```
Phase 3 第3位-2：子QA并行测试
    ↓

    ↓

    ↓

    ↓
5. 验证历史问题是否已解决
    ↓
6. 发现新问题 → 记录到经验库
    ↓

```

**子QA经验库操作**：
- **测试前读取**: 了解自己负责模块的历史问题
- **测试中对比**: 确保不重复犯错，不引入历史问题
- **测试后记录**: 将新问题记录到经验库
- **回归测试**: 验证历史问题是否回归

## 注意事项

### 总结模式（项目完成后）

1. **不要假设**: 不要假设用户没有问题，必须主动询问
2. **完整记录**: 每个问题都要完整记录，包括解决过程
3. **分类清晰**: 经验记录要按项目类型和问题类型双重分类
4. **持续更新**: 每次全栈开发后都要更新经验库
5. **前置应用**: 新项目的开发必须参考历史经验

### 查询模式（新项目需求分析阶段）

1. **必须在分派子策划前执行**: 查询经验库是阻塞点，未完成前禁止分派子策划
2. **全面匹配**: 不仅要匹配项目类型，还要匹配需求关键词和技术栈
3. **生成报告**: 必须生成《经验借鉴报告》并附加到需求文档
4. **实际应用**: 主策划必须根据经验调整设计，不能只是形式上的查询
5. **传递经验**: 在分派子策划时，必须告知相关历史风险和规避措施
6. **更新验收标准**: 在验收标准中增加针对历史问题的检查项

### 查询模式话术模板

**主策划请求查询经验库**：
> 我已经完成需求拆分，请查询项目经验库，获取以下相关经验：
> - 项目类型：[RPG/SLG/休闲等]
> - 关键功能：[技能系统/UI布局/网络同步等]
> - 技术栈：[Unity/Web/Node.js等]
> 
> 请生成《经验借鉴报告》，帮助我规避已知问题。

**经验查询结果返回**：
> 📚 **经验借鉴报告已生成**
> 
> 根据您的项目类型和需求，我从经验库中找到了[X]条相关经验：
> 
> **高风险项**（历史上多次发生）：
> 1. [风险1] - 建议措施：...
> 2. [风险2] - 建议措施：...
> 
> **中风险项**：
> 1. [风险3] - 建议措施：...
> 
> **设计建议**：
> - 建议1：...
> - 建议2：...
> 
> 请将本报告附加到需求文档中，并在分派子策划时告知相关风险。

**主策划向子策划传递经验**：
> 在分配任务时，请特别注意以下历史经验：
> 
> **已知风险**（来自经验库）：
> - [功能点]：历史上曾出现[问题描述]，请在本项目中注意[规避措施]
> 
> **设计建议**：
> - [建议内容]
> 
> 请在设计和开发过程中主动规避这些问题。
