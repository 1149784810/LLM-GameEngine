> **术语引用**：[terminology-standard](.trae/skills/terminology-standard/SKILL.md)

---

## 功能概述

本技能负责建立标准化的问题追踪机制，包括：
- 记录所有发现的Bug和问题
- 跟踪Bug的修复状态
- 管理Bug的生命周期
- **防止"按下葫芦浮起瓢"** - 每次修改后验证原有功能
- 建立Bug知识库，避免重复问题
- **⭐强制记录经验** - 每次修复后必须记录到经验库并更新缓存

> **注意**：
> - 回归测试(RT)的标准定义参见 [qa-standards-manager](.trae/skills/qa-standards-manager/SKILL.md)
> - **经验记录是强制要求**，修复后必须执行

---

## ⚠️ 核心原则：Bug必须闭环

### Bug生命周期

```
发现Bug → 记录Bug → 分配修复 → 修复中 → 待验证 → 验证通过 → 关闭
              ↑                                    |
              └──────────── 验证失败 ──────────────┘
```

### 禁止行为

| 禁止行为 | 后果 | 正确做法 |
|----------|------|----------|
| 发现Bug不记录 | 遗漏问题 | 立即记录到Bug清单 |
| 修复后不验证 | 可能引入新问题 | 修复后必须验证 |
| 验证后不关闭 | 状态混乱 | 验证通过后立即关闭 |
| 跳过回归测试(RT) | 改好A后B出错 | 每次修改后执行回归测试(RT) |
| **修复后不记录经验** ⭐新增 | 经验无法传承 | **强制记录到经验库并更新缓存** |

## Bug修复流程

### 标准修复流程

```
┌─────────────────────────────────────────────────────────────┐
│                     Bug修复流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 发现Bug                                                  │
│     └── 记录到Bug清单                                        │
│           ↓                                                 │
│  2. 分析原因                                                 │
│     └── 确定根本原因                                         │
│     └── 评估影响范围                                         │
│           ↓                                                 │
│  3. 分配修复                                                 │
│     └── 分配给对应开发人员                                   │
│     └── 更新Bug状态为"修复中"                                │
│           ↓                                                 │
│  4. 实施修复                                                 │
│     └── 修改代码                                             │
│     └── 本地测试                                             │
│     └── 更新Bug状态为"待验证"                                │
│           ↓                                                 │
│  5. 回归测试(RT) ⭐关键步骤                                   │
│     └── 验证修复的问题已解决                                 │
│     └── 验证未引入新问题                                     │
│     └── 验证原有功能正常                                     │
│           ↓                                                 │
│  6. 验证结果                                                 │
│     ├── 通过 → 关闭Bug                                       │
│     └── 不通过 → 返回步骤3重新修复                           │
│           ↓                                                 │
│  7. 记录经验 ⭐强制步骤                                      │
│     └── 记录到经验库: experience-db.md                       │
│     └── 更新缓存计数: experience-cache-manager.js            │
│     └── 生成经验记录文档                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Bug修复后强制经验记录流程 ⭐新增

**修复完成后必须执行：**

```
Bug验证通过
    ↓
【强制】记录经验到经验库
    ↓
1. 生成经验记录
   node bug-experience-recorder.js record --bug-id=<BugID>
    ↓
2. 更新缓存计数
   node experience-cache-manager.js match --id=<缓存ID>
    ↓
3. 保存经验记录
   追加到 experience-db.md
    ↓
经验记录完成，Bug完全闭环
```

**经验记录检查清单：**

```markdown
## Bug修复后经验记录检查清单

### 必须完成
- [ ] Bug已修复并验证通过
- [ ] 已分析根本原因
- [ ] 已记录经验到 experience-db.md
- [ ] 已更新缓存计数（如匹配缓存条目）
- [ ] 已生成经验记录文档

### 经验记录内容
- [ ] 项目类型
- [ ] 问题类型
- [ ] 问题描述
- [ ] 根本原因
- [ ] 解决方案
- [ ] 预防措施
- [ ] 相关文件
- [ ] 记录时间

### 缓存更新
- [ ] 检查是否匹配现有缓存条目
- [ ] 如匹配，执行: node experience-cache-manager.js match --id=<ID>
- [ ] 如不匹配，考虑创建新缓存条目
```

### 回归测试(RT)检查清单（修复后必须执行）

> **引用**：[qa-standards-manager](.trae/skills/qa-standards-manager/SKILL.md)

```markdown
## 回归测试(RT)清单

### 修复验证
- [ ] Bug [ID] 已修复，复现步骤不再触发问题
- [ ] 修复代码已提交

### 影响范围验证
- [ ] 修复的模块功能正常
- [ ] 相关模块功能正常
- [ ] 无新增错误

### 原有功能验证⭐关键
- [ ] 主流程功能正常
- [ ] 核心功能正常
- [ ] 无"按下葫芦浮起瓢"情况

### 控制台检查
- [ ] 浏览器控制台无红色错误
- [ ] 无新增警告信息

### 结论
- [ ] 回归测试(RT)通过，可以关闭Bug
- [ ] 回归测试(RT)不通过，需要继续修复
```

## 防止"按下葫芦浮起瓢"

### 问题分析

**什么是"按下葫芦浮起瓢"？**
- 修复了问题A，但导致问题B出现
- 修改了功能X，但功能Y失效
- 解决了Bug，但引入了新的Bug

### 预防措施

#### 1. 修改前分析

```markdown
## 修改影响分析

### 修改内容
[描述要修改的内容]

### 影响范围分析
- [ ] 直接影响的模块: [模块名]
- [ ] 间接影响的模块: [模块名]
- [ ] 相关的功能: [功能名]

### 需要回归测试(RT)的功能
- [ ] 功能1: [名称]
- [ ] 功能2: [名称]
- [ ] 功能3: [名称]
```

#### 2. 修改后验证

**每次修改后必须执行：**
1. 验证修复的问题已解决
2. 验证直接相关的功能正常
3. 验证间接相关的功能正常
4. 验证主流程功能正常
5. 检查控制台无错误

#### 3. 回归测试(RT)策略

| 修改类型 | 回归测试(RT)范围 | 测试重点 |
|----------|------------------|----------|
| Bug修复 | 修复点 + 相关功能 | 修复是否有效 |
| 功能新增 | 新功能 + 原有功能 | 无冲突 |
| 代码重构 | 全量功能 | 功能一致性 |
| 配置修改 | 相关模块 | 配置生效 |

## Bug知识库

### 常见Bug类型及预防

#### 类型1: 功能失效类

**常见表现：**
- 点击按钮无响应
- 功能完全失效
- 游戏无法启动

**常见原因：**
- ES Module CORS问题
- 类未暴露到全局
- 常量定义顺序错误
- DOM事件绑定失效

**预防措施：**
- 使用传统脚本方式
- 每个文件末尾暴露到window
- 常量定义在文件开头
- 统一事件绑定

#### 类型2: 流程中断类

**常见表现：**
- 点击开始游戏无法进入
- 界面无法切换
- 游戏卡在某个状态

**常见原因：**
- 状态管理混乱
- 条件判断错误
- 异步处理不当

**预防措施：**
- 使用StateManager集中管理状态
- 添加调试日志
- 完整的异常处理

#### 类型3: 数值错误类

**常见表现：**
- 伤害计算错误
- 得分不正确
- 数值显示异常

**常见原因：**
- 计算公式错误
- 数据类型问题
- 单位不一致

**预防措施：**
- 数值公式文档化
- 单元测试
- 边界值测试

#### 类型4: UI显示类

**常见表现：**
- UI布局错乱
- 文字显示不全
- 图片加载失败

**常见原因：**
- 响应式适配问题
- 资源路径错误
- 样式冲突

**预防措施：**
- 多分辨率测试
- 资源路径检查
- 样式隔离

## 使用方式

### 调用示例

**发现Bug时：**
```
发现Bug
    ↓
bug-tracker:
    1. 记录Bug信息
    2. 分配严重程度(P0/P1/P2/P3)
    3. 分配给修复人
    4. 更新Bug清单
    ↓
通知相关人员
```

**修复Bug时：**
```
开始修复
    ↓
bug-tracker:
    1. 更新Bug状态为"修复中"
    2. 实施修复
    3. 本地测试
    4. 更新Bug状态为"待验证"
    5. 执行回归测试(RT)
    6. 验证通过 → 关闭Bug
    7. 验证不通过 → 重新修复
```

### 集成到开发流程

```
Phase 3 策划验收
    ↓
发现Bug
    ↓
记录到Bug清单
    ↓
分配给开发人员修复
    ↓
修复完成
    ↓
执行回归测试(RT)
    ↓
验证通过 → 关闭Bug
    ↓
继续验收
```

## 注意事项

1. **立即记录**：发现Bug后立即记录，不要拖延
2. **详细描述**：Bug描述要详细，便于复现
3. **必须回归**：每次修改后必须执行回归测试(RT)
4. **闭环管理**：Bug必须经历完整的生命周期
5. **知识积累**：常见Bug要记录到知识库
6. **预防为主**：从历史Bug中学习，预防同类问题
7. **测试标准**：回归测试(RT)标准参见 [qa-standards-manager](.trae/skills/qa-standards-manager/SKILL.md)
