## 功能概述

本技能是**测试标准的唯一权威来源**，负责制定和管理游戏开发的验收标准，包括：
- 制定各阶段的验收标准
- 定义检查清单和验收项
- 管理质量门槛和通过准则
- 提供验收报告模板
- **强制执行测试流程** - 功能测试(FT)、视觉测试(VT)、完整路径测试(FPT)、回归测试(RT)
- **截图验证功能** - 自动打开应用、截图并进行视觉需求验证
- **经验库集成** - 测试前读取经验库，测试后更新经验库

> **注意**：本技能定义测试标准，测试执行由 **主测试(LT)** 分配任务，**子QA** 并行执行测试。
> 
> **引用**：[project-experience-summarizer](.trae/skills/project-experience-summarizer/SKILL.md) - 经验库管理

## ⚠️ 核心原则：测试不可跳过

### 强制测试要求

**以下测试环节绝对禁止跳过：**

| 测试类型 | 英文标识 | 优先级 | 是否可跳过 | 跳过后果 |
|----------|---------|--------|------------|----------|
| **功能测试** | FT (Functional Test) | P0 | ❌ 绝对禁止 | 无法发现功能缺陷 |
| **视觉测试** | VT (Visual Test) | P0 | ❌ 绝对禁止 | UI问题无法发现 |
| **完整路径测试** | FPT (Full Path Test) | P0 | ❌ 绝对禁止 | 流程中断bug |
| **回归测试** | RT (Regression Test) | P0 | ❌ 绝对禁止 | 改好A后B出错 |
| **性能测试** | PT (Performance Test) | P1 | ⚠️ 需审批 | 性能问题 |

## 验收标准体系

### 验收等级定义

| 等级 | 代码 | 描述 | 处理策略 |
|------|------|------|----------|
| 通过 | PASS | 完全符合验收标准 | 可以进入下一阶段 |
| 有条件通过 | CONDITIONAL | 基本符合，存在轻微问题 | 记录问题，限时修复 |
| 不通过 | FAIL | 不符合验收标准 | 必须修复后重新验收 |

### 问题优先级定义

| 优先级 | 代码 | 描述 | 处理要求 |
|--------|------|------|----------|
| **P0 - 阻塞** | BLOCKER | 导致系统无法运行或核心功能失效 | **必须修复，否则无法通过** |
| **P1 - 严重** | CRITICAL | 严重影响用户体验 | **应该修复，影响通过评估** |
| P2 - 一般 | MAJOR | 影响部分功能或体验 | 建议修复，记录跟踪 |
| P3 - 轻微 | MINOR | 轻微问题或优化建议 | 可以遗留，后续版本处理 |

#### 完整路径测试(FPT)说明 ⭐最高优先级

**测试目标：**
确保游戏中所有功能路径完全通畅，从入口到出口的完整用户旅程无任何阻塞。

**测试内容：**
1. **主流程路径**：核心玩法完整流程
2. **分支路径**：所有可选功能路径
3. **异常路径**：错误处理和边界情况
4. **回退路径**：返回、取消、退出功能

**测试方法：**
- **程序测试**：通过Log验证代码执行路径
- **视觉测试(VT)**：通过截图验证界面跳转和显示
- **实际点击测试**：QA必须实际点击每个按钮

**强制检查项（QA必须逐项勾选）：**
```markdown

- [ ] 分支2: [描述] - 通过/不通过

- [ ] 按钮1: [名称] - 点击有响应/无响应
- [ ] 按钮2: [名称] - 点击有响应/无响应

### 控制台检查
- [ ] 无红色错误
- [ ] 无警告信息
```

## 截图验证功能

### 功能说明

验收标准管理器具备自动截图验证能力，用于验证应用界面是否符合视觉和功能需求：
- 自动打开目标应用程序
- 将应用窗口置于屏幕最前方
- 执行截图并保存到指定目录
- 使用视觉分析验证界面元素
- 生成截图验证报告

### 截图目录结构

```
工作区/
└── screenshots/              # 截图根目录
    ├── raw/                  # 原始截图
    ├── annotated/            # 标注截图（带验证标记）
    └── reports/              # 截图验证报告
```

### 视觉测试(VT)检查项

| 检查项 | 验证内容 | 优先级 |
|--------|----------|--------|
| 界面跳转 | 点击后是否正确跳转到目标界面 | P0 |
| 布局符合度 | 是否符合UI布局文档要求 | P0 |
| 元素完整性 | 所有UI元素是否正确显示 | P0 |
| 文字内容 | 文字是否正确、清晰 | P1 |
| 图片资源 | 图片是否正确加载 | P1 |
| 动画效果 | 转场动画是否正常 | P2 |
| 响应反馈 | 点击是否有视觉反馈 | P1 |

## 经验库集成流程 ⭐新增

### 测试前读取经验库

**主测试(LT)职责**：
1. **读取经验库**：
   - 读取 `.trae/skills/project-experience-summarizer/experience-db.md`
   - 筛选与当前项目相关的历史经验
   - 识别高风险点和常见问题

2. **制定规避措施**：
   - 根据历史经验制定测试重点
   - 在测试计划中增加针对历史问题的检查项
   - 准备历史问题的验证方法

3. **告知子QA**：
   - 将历史风险点告知所有子QA
   - 要求子QA测试前读取经验库
   - 强调避免重复犯错的重要性

**子QA职责**：
1. **测试前读取**：
   - 每个子QA测试前必须读取经验库
   - 了解自己负责模块的历史问题
   - 制定针对性的测试策略

2. **测试中对比**：
   - 测试时对比历史问题清单
   - 验证历史问题是否已解决
   - 确保不引入已修复的历史问题

### 测试后更新经验库

**发现问题时**：
1. **记录问题**：
   - 详细描述问题现象
   - 记录复现步骤
   - 分析问题根因

2. **更新经验库**：
   - 将新问题记录到经验库
   - 分类：项目类型、问题类型、严重程度
   - 记录解决方案和预防措施

**引用**：[project-experience-summarizer](.trae/skills/project-experience-summarizer/SKILL.md) - 经验记录格式

## 注意事项

1. **测试不可跳过**：功能测试(FT)、视觉测试(VT)、完整路径测试(FPT)、回归测试(RT)绝对禁止跳过
2. **P0问题必须修复**：任何P0级问题都必须修复后才能通过验收
3. **完整路径测试**：子QA必须实际运行游戏，验证所有路径通畅
4. **控制台检查**：必须检查浏览器控制台是否有错误
5. **回归测试**：每次修改后必须执行回归测试(RT)
6. **截图留档**：视觉测试必须截图留档作为证据
7. **术语一致**：所有测试类型使用标准术语：FT、VT、FPT、RT
8. **经验库强制使用**：测试前必须读取经验库，测试后必须更新经验库
9. **禁止自测**：所有测试由子QA执行，程序不执行自测
