“启动游戏开发”：代表要调用全栈开发引擎进行一个完整流程的游戏开发

"启动测试框架"：代表调用名为引擎测试框架的技能对这个引擎开发流程和框架完整度进行测试

"pull"：代表同步远端仓库到本地目录

以下行为是**绝对强制**的，智能体**必须**遵守，**禁止**以任何理由跳过：

## 0. 上下文缓冲区强制执行（新增）

### 0.1 上下文文件生命周期
- **进入新阶段或新智能体开始工作时**：**必须**首先读取上下文文件（第一个操作）
- **执行最后一个任务后**：**必须**更新上下文文件（最后一个操作）
- **禁止**在未读取上下文的情况下开始阶段工作
- **禁止**在未更新上下文的情况下结束阶段工作

### 0.2 上下文文件内容强制执行
每个上下文文件**必须**包含以下部分：
- **【必须执行】**：下个阶段必须要做的事情（清单）
- **【绝对禁止】**：下个阶段绝对禁止做的事情（清单）
- **【已完成】**：当前阶段做了的事情（清单）
- **【执行状态】**：当前阶段最终的执行情况（诚实记录，反幻觉）
- **【伴生技能】**：当前阶段和下个阶段都要继续保持和运行的伴生技能列表

### 0.3 上下文文件命名规范
- 格式：`PHASE-[阶段号]-[步骤号]-[行为描述]-[时间戳].md`
- 示例：`PHASE-4-Step-3-3-[QA测试]-20260220-143052.md`
- **禁止**使用非规范命名的上下文文件

### 0.4 上下文操作审计
- **必须**使用 `context-manager` 技能进行上下文操作
- **必须**验证上下文文件读取成功
- **必须**验证上下文文件更新成功
- 上下文操作失败**必须**阻塞流程继续

## 1. QA测试强制执行

### 1.1 视觉测试(VT)强制执行
- **必须**在浏览器中全屏打开游戏（禁止使用OpenPreview）
- **必须**使用 `take_screenshot.ps1` 脚本执行全屏截图
- **必须**在声称VT通过前，验证 `screenshots/` 目录存在PNG文件
- **禁止**仅凭代码阅读声称VT通过
- **禁止**创建MD文档代替PNG截图

### 1.2 截图验证强制执行
- 每个测试步骤**必须**包含：操作前截图 + 操作后截图
- **必须**使用 `LS` 工具验证截图文件存在
- **必须**验证截图文件大小 > 0
- **无截图证据 = 测试未执行**，禁止声称测试通过

### 1.3 阻塞点强制执行
- 遇到标记为【阻塞】的步骤，**必须**等待验证完成才能继续
- **禁止**跳过任何标记【阻塞】的步骤
- **禁止**假设阻塞步骤已通过而不验证

## 2. 技能调用强制执行

### 2.1 前置技能强制执行
- 执行QA测试前**必须**调用 `qa-standards-manager` 技能
- 执行契约验证前**必须**调用 `contract-validator` 技能
- 执行上下文操作前**必须**调用 `context-manager` 技能
- **禁止**在技能未调用的情况下执行相关操作

### 2.2 输出契约强制执行
- 生成任何输出前**必须**调用 `output-normalizer` 技能
- **禁止**在未确定输出位置的情况下创建文件

## 3. 反幻觉强制执行

### 3.1 证据优先原则
- **无证据 = 未发生**，禁止声称完成了没有证据的操作
- **禁止**虚构工具调用结果
- **禁止**假设操作成功而不验证

### 3.2 自检清单强制执行
- 完成QA测试后**必须**执行反幻觉自检
- **必须**逐项确认自检清单
- **禁止**跳过自检直接生成报告

## 4. 工具调用审计

### 4.1 强制工具调用追踪
以下工具调用会被自动审计：
- `take_screenshot.ps1` - 截图工具（VT必需）
- `window-manager.ps1` - 窗口管理（VT必需）
- `RunCommand` 启动Web服务器（环境准备必需）
- `context-manager` - 上下文管理（阶段必需）

### 4.2 审计失败处理
- 如果缺少必需的工具调用，**必须**停止生成报告
- **必须**补充执行缺失的工具调用
- **禁止**在审计失败的情况下声称测试完成

## 5. 八层强制执行架构（新增）

### 5.1 架构层次
```
Layer 1: Context Buffer (上下文缓冲区)
Layer 2: QA Execution Monitor (QA执行监督)
Layer 3: QA Standards Manager (QA标准管理)
Layer 4: Contract Validator (契约验证)
Layer 5: State Manager (状态管理)
Layer 6: Phase Stage Guard (阶段守卫)
Layer 7: PL Authority Guard (权限守卫)
Layer 8: Flow Strategy (流程策略)
```

### 5.2 强制执行规则
- 每层都有明确的输入输出契约
- 每层都对下一层进行监督和验证
- 任何一层验证失败都**必须**阻止流程继续
- 所有层必须协同工作，形成完整的强制执行链
