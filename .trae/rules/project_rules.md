指令错一个字都不能执行对应的行为
“启动游戏开发”：代表要调用全栈开发引擎进行一个完整流程的游戏开发

"启动测试框架"：代表调用名为引擎测试框架的技能对这个引擎开发流程和框架完整度进行测试

“项目经验总结”：代表排查问题并调用项目经验总结的技能进行归纳和更新

“push”：代表本地变更推送到远端git仓库

"pull"：代表同步远端仓库到本地目录

！！！！强制执行条款（新增）！！！！

以下行为是**绝对强制**的，智能体**必须**遵守，**禁止**以任何理由跳过：

## 1. QA测试强制执行

### 1.1 视觉测试(VT)强制执行
- **必须**在浏览器中全屏打开游戏（禁止使用OpenPreview）
- **必须**使用 `take_screenshot.ps1` 脚本执行全屏截图
- **必须**在声称VT通过前，验证 `screenshots/` 目录存在PNG文件
- **禁止**仅凭代码阅读声称VT通过
- **禁止**创建MD文档代替PNG截图

### 1.2 截图验证强制执行
- 每个测试步骤**必须**包含：操作前截图 + 操作后截图
- **必须**使用 `LS` 工具验证截图文件存在
- **必须**验证截图文件大小 > 0
- **无截图证据 = 测试未执行**，禁止声称测试通过

### 1.3 阻塞点强制执行
- 遇到标记为【阻塞】的步骤，**必须**等待验证完成才能继续
- **禁止**跳过任何标记【阻塞】的步骤
- **禁止**假设阻塞步骤已通过而不验证

## 2. 技能调用强制执行

### 2.1 前置技能强制执行
- 执行QA测试前**必须**调用 `qa-standards-manager` 技能
- 执行契约验证前**必须**调用 `contract-validator` 技能
- **禁止**在技能未调用的情况下执行相关操作

### 2.2 输出契约强制执行
- 生成任何输出前**必须**调用 `output-normalizer` 技能
- **禁止**在未确定输出位置的情况下创建文件

## 3. 反幻觉强制执行

### 3.1 证据优先原则
- **无证据 = 未发生**，禁止声称完成了没有证据的操作
- **禁止**虚构工具调用结果
- **禁止**假设操作成功而不验证

### 3.2 自检清单强制执行
- 完成QA测试后**必须**执行反幻觉自检
- **必须**逐项确认自检清单
- **禁止**跳过自检直接生成报告

## 4. 工具调用审计

### 4.1 强制工具调用追踪
以下工具调用会被自动审计：
- `take_screenshot.ps1` - 截图工具（VT必需）
- `window-manager.ps1` - 窗口管理（VT必需）
- `RunCommand` 启动Web服务器（环境准备必需）

### 4.2 审计失败处理
- 如果缺少必需的工具调用，**必须**停止生成报告
- **必须**补充执行缺失的工具调用
- **禁止**在审计失败的情况下声称测试完成

深度思考业务列表：
启动全栈游戏开发
游戏相关的BUG修复

！！！！其余规范！！！！

输出任何文件和资产时都需要调用输出规范器的技能，确定应该输出文件到什么位置

在用户使用“启动游戏开发”的指令时，应该先读取相关的技能组，再进行进一步操作，确保所有流程都按要求进行

在用户发起特定领域或功能的需求时，应该先确认用户的需求，再根据需求调用相关的技能组，确保提供的信息准确、详细

每次更新了技能或者新建了技能之后都要自行push到远端git仓库，确保技能组的更新及时生效

每当创建游戏开发相关或者引擎流程相关的技能时，都需要先调用技能优化器的技能，用来指导新技能的创建和优化

若是在项目经验总结阶段或者是某个游戏的bug排查阶段，需要在解决问题之后主动更新项目经验库及其索引缓存表，确保后续可以快速定位和解决类似问题
